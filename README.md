# Revisiting phylogenetic relationships of Pycnodontiformes: New insights from Bayesian inference

Vítor P. G. Costa, [Henrique L. Rieger](https://github.com/henrieger), Tito Aureliano, Aline M. Ghilardi, [Gustavo A. Ballen](https://github.com/gaballench)

---

This repository contains scripts, data and results used in the [paper](<>) for Bayesian phylogenetic inference and divergence-time estimation (DTE) of pycnodontiform fishes. Directories are supposed to be run sequentially (from `00_*` to `02_*`), as steps down the line require outputs from previous steps. Each directory is divided into a `combined` and `partitioned` subdirectory, for the analyses considering a single partition of the data and 9 morphological partitions, respectively (see the main document).

Many files in the repository are outputs from software and are presented as to provide verifiable and reproducible results for this work, but a cleanup of these is recommended for each step. Each directory will therefore have a `clean.sh` that erases all generated files for new analyses to be run, maintaining only data and scripts. Use with caution.

## Bayesian phylogenetic tree inference

Directory `00_tree_inference` is dedicated to inference of the phylogenetic tree inference and relative branch lengths using [MrBayes](<>). For each of `combined` and `partitioned`, a script named `00_run_inference.sh` executes the correct MrBayes command and script, assuming the MPI version of the software is correctly installed and accessible through either the `mb-mpi` or `mb` command. The outputs of the software are then dumped in its correspondent directory to be used by subsequent steps.

The analyses uses 4 independent runs, each running 4 chains (1 cold and 3 heated), so ideal conditions are for a machine with at least 16 threads. Total number of independent threads can be changed in the script by altering the value of the `-n` argument. Each run generates an independent output file, with an extension prefixed by its ID. Output files of log summarization steps lack this number.

This step also generates a `*.con.tre` file with the Majority Rule Consensus (MRC) of the inferred trees for each partition scheme. These are then edited used FigTree to generate files named `figtree.nex`, which were exported to SVG and subsequently imported and manually edited in Inkscape to generate the plot `final.svg` in the root of the directory. This file contains the coplot of the MRCs for both schemes, showcasing their differences.

## Maximum clade credibility tree

DTE analysis requires a rooted, strictly bifurcating tree as input, which the MRC generated by MrBayes is not. We can therefore calculate one using the trace of all outputs from MrBayes using the Maximum Clade Credibility (MCC) criterion, which instead retrieves the compatible bifurcations with the most support througout the analysis.

MCC tree computing is done in directory `01_mcctree`. For each partition scheme subdirectory, a script named `00_calculate_maxcredtree.sh` runs a pipeline with [PhyX](<>) to create a NEXUS file with combined trees from all MrBayes independent runs and [TreeAnnotator](<>) to calculate the MCC tree. Then, `01_reroot_tree.R` takes the resulting consensus and roots it to the correct outgroup, _Polypterus senegalus_.

## Divergence-time estimation

DTE was carried-out using MrBayes' tip-dating implementation, which receives as input the morphological alignment, MCC tree and dating priors for each fossil leaf. The process is scripted in directory `02_divergence`.

Dates for priors were assessed using occurrence data from the [Paleobiology Database](https://paleobiodb.org/), from which original downloaded files (`pycnodontiformes.csv` and `pteronisculus.csv`) are available in the root of the directory, but manually input to `.mb` files accordingly.

The script `00_join_alignment_tree.sh` in each subdirectory concatenates the alignment files specified in the tree inference directory and MCC Newick tree into a single NEXUS file `alignment_and_tree.nex`.

Analyses can be subdivided again into sampling of `prior` and `posterior` distributions for each node, but posteriors is what we are mostly interested in. Script `01_run_inference.sh` runs the correct MrBayes command, again assuming the MPI version is being used. Sampling was done using a single run and 8 chains (1 cold and 7 heated), for which the ideal is at least 8 CPU threads.

The partitioned posterior `.con.tre` file is what is used for the final plot in the paper. Again, this file is edited in FigTree and saved into `figtree.nex`, which is exported to SVG and edited by hand in Inkscape to achieve the desired result `calibrated.svg`.
